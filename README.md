# 记者选拔回避与复核

联合选拔初评后的复核服务：在报名、回避、评分、事件确认和终局决定的既有事件约定上，
解决"迟到利益关系下评委分数是否还进入排名""跨组兼报哪些结论可共用"以及申诉更正问题。

## 模型

事件溯源：所有状态由只追加的领域事件重放得到（`src/store.js` 为 JSONL 存储），
服务无其他持久化状态，重启后按原截止时间继续运行。事件信封与全部事件类型见
`contracts/domain.schema.json` 与 `src/domain.ts`，工厂在 `src/events.js`，
业务规则在 `src/review.js`。

### 规则约定

- **材料按版本保存**：版本号只能新增、不能覆盖；评分与资格结论都锚定具体材料版本。
- **受派冻结**：评委受派（`ASSIGNMENT_FROZEN`）时只收录当时已申报的利益关系；
  冻结之后才到的关系视为迟到关系。
- **迟到关系只暂停、不删除**：`LATE_INTEREST_RECEIVED` 把该评委对该候选人仍有效的
  评分置为 `SCORE_SUSPENDED`（原 `SCORE_SUBMITTED` 与暂停理由永久保留），
  并关闭该评委对此候选人的后续评分通道；其他评委、其他候选人的评分不受影响。
- **回避与替补**：回避确认受组别回避截止时间约束；替补人选必须由既不同于原评委
  所属机构、也不同于替补本人机构的第三方机构批准；替补意见对原评委不可见
  （`substituteView` 对原评委返回 `null`）。
- **分组独立、资格可复用、评分隔离**：各组独立排序；跨组兼报时资格结论可复用
  （结论与依据材料版本必须一致，事件记录 `reused_from_group`）；
  评分严格按组隔离，受派组别与评分组别不符即拒绝。
- **申诉**：必须指向具体材料版本（`MATERIAL_VERSION`）或程序事件（`INCIDENT`），
  且在组别申诉截止时间内提出。
- **双角色签署**：重新评分与最终裁决、裁决更正都需两名**不同角色、不同自然人**
  签署；第二名签署后重新评分才生效（旧评分置 `REPLACED`，新评分带
  `rescore_appeal_id`），裁决才可以公布。
- **公布后只能追加更正**：`DECISION_FINALIZED` 后不能再改原公布；更正走
  `DECISION_CORRECTION_PROPOSED` → 两次 `CORRECTION_SIGNATURE_ADDED` →
  `CORRECTION_PUBLISHED`，原公布与更正都保留，当前序列取最新一次已公布更正。
- **请求幂等**：同一 `requestNo` 完全相同的请求直接回放原结果、不产生新事件；
  同编号异内容按冲突拒绝（`REQUEST_SEEN` 记录哈希）。

### 分数反查

`explainScore(scoreId)` 返回一项分数的 `effectiveStatus`
（`ACTIVE` / `SUSPENDED` / `REPLACED` / `EXCLUDED`）、是否计入排名、
逐条理由以及完整事件链（提交、暂停、重评），可直接回答"这项分数为何有效或被排除"。

## 命令入口（验收演示）

```bash
npm run demo      # node src/cli.js demo
```

端到端演示：

1. 迟到利益关系导致评分暂停、评委回避、**不同机构批准替补并接管评分**；
2. **两个组别独立排序、各自双角色签署并同时裁决公布**（资格结论跨组复用）；
3. 公布后申诉指向具体材料版本，双签重新评分后**追加更正，最终序列变化**，
   另一组序列不受影响；

并附带：完全重复请求回放 / 同编号异内容冲突、重启后按原截止时间继续、
以及对有效分、暂停分、替补分（被替代）的 `explainScore` 反查。

## 领域边界

事件一旦被接收，其标识、发生时间和版本不应被原地改写；业务更正一律产生后继记录。
涉及个人、机构或商业敏感信息时（如替补内部意见），调用方只读取完成职责所必需的字段，
原评委不得读取替补意见。
